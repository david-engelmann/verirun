## Carried item C1, audit finding F9, assigned to round P1

Temp file names combine the process id, a fixed worker id, and a process wide atomic counter, created with create_new. After pid reuse, a name can collide with crash debris from an earlier process and fail a put spuriously. The failure is safe and never corrupts. The audit deferred it until a cheaper cross process uniqueness source is chosen. The perfection programme takes it in P1, where temp names gain a cross process uniqueness source inside the store adapter, gated by a collision test that fails against the old naming. Closed in round P1 (see the rounds section below): the names now carry a per-process nonce the store adapter mints once from the clock, and the collision test stands in the store's cas_temp_names suite.

## Workstream records

### W1. The Windows runner core

The runner now compiles and runs on Windows. Process control goes through a new internal crate, verirun-platform, which holds the workspace's only unsafe blocks behind a safe ProcessGroup API. On Unix the group is the mechanism the runner has always used, the child leading its own process group and termination signalling the group through the shell builtin. On Windows the group is a job object created with kill on job close, assigned the child immediately after spawn, and terminated as a whole at the deadline. Executable resolution on Windows applies the PATHEXT snapshot to bare names and treats the executable extensions as the executable test, where Unix uses permission bits. A portable runner test suite proves exit codes, the hermetic environment, byte exact capture, and whole tree termination with the same test text on both platforms, and the Windows CI job runs it. Two consequences are recorded. The platform crate is a fourth workspace crate and a dependency of the store crate, so the next release publishes it alongside the existing three. Assignment immediately after spawn leaves a narrow window in which a child could spawn a process outside the job; the window is the same class the Unix group has always had with session creation, and the drain grace bounds its cost.

The first hosted run of the portable suite failed all four tests, and a staged probe on a throwaway branch isolated the failure below the runner, in the store: the seam attached and terminated cleanly, resolution worked, and execution died inside the put protocol. Two Windows file semantics differences in the put's final step are fixed in this slice because its gate cannot pass without them, and both are recorded here rather than smoothed over. First, the rename at the end of a put raced a concurrent put of the same digest: the presence check passed for both, the winner set the object read-only, and the loser's rename was refused because Windows will not replace a read-only file where Unix replaces identical bytes silently. A failed rename whose destination now exists completes the way the discard path does, syncs and phases included. Second, directory sync has no Windows equivalent, so the step is a no-op there in this slice. That is a real durability difference, and it is carried to W4, whose slice re-proves this protocol under Windows file semantics and writes the mapping down.

With those two fixes in, three of the four portable tests pass on Windows and the runner itself probes clean end to end. The remaining failure is the hermetic environment test's expectation, not the runner: a staged dump of the environment inside a task shows exactly the runner's five pairs, plus three variables `cmd` synthesizes for itself when they are absent (its own path, its extension list, and its prompt). The test now removes those three on Windows before its exact comparison, the same shell bookkeeping that makes the Unix side run the `env` program directly rather than a shell, so the comparison stays exact over everything the runner controls.

### W2. Pipes, draining, and timeout parity

The drain machinery was already platform neutral, so this slice adds its gate evidence to the portable suite and changes no production code. The volume case runs eight mebibytes on each stream in one task with both streams in flight together and asserts the captured blobs byte for byte against patterns built in process. The timeout case has the child write a known prefix, flush it, and sleep holding both pipes; the captured stream equals exactly the prefix. A third case, Unix only, detaches a writer that escapes the tree kill, so the ten second drain grace and the stream cutoff are exercised directly and the finalized stream is an exact prefix of the endless stream with the cut noted. Windows children cannot break out of their job object, so on Windows the grace parity rests on the shared collection code and the prefix case, and this entry states that plainly rather than claiming a Windows cutoff run. Hosted evidence: this slice's own pull request CI, whose windows job runs the grown portable suite on windows-latest and whose rust job runs it inside the full workspace suite, both green on the merged head. No production difference was forced by the evidence.

## Perfection rounds

### P1. Correctness, first cycle

The round's named assignment is carried item C1, audit finding F9, and it lands here. Temp file names in the store now carry a per-process nonce as a final component before the extension, in both the known digest and streamed shapes. The store adapter mints the nonce once per process from its clock module, mixed with the process id; the core naming functions stay pure and take the nonce as a new parameter, which is a breaking change to those two functions under the pre-1.0 versioning policy. The architecture text is updated in the same landing, and its old doctrine sentence, that uniqueness comes from the tuple and never from the clock, is replaced rather than left standing against the code. The gate is the collision test in the store's cas_temp_names suite: it plants debris under exactly the names the old scheme minted for the test process's own pid, across the counter range a fresh process reaches first, and both put shapes then succeed; against the old naming the first put's create_new meets the debris and fails. The failure F9 described was always safe and never corrupting, and the fix keeps create_new semantics untouched, so a genuine same-process collision still fails safe rather than overwriting. No new findings were raised by this round's read of the temp and debris area: the garbage collector's stale temp handling reads file ages, not names, and is unaffected, and the work root and collection locks mint fixed names under their own staleness rules, which F8 already settled.
